# Pilot readiness review

Decide whether mobile job notes can start or resume its limited pilot. Run this workflow when the required evidence is available, not merely because a target date arrives.

## Inputs

- The current [acceptance criteria](../projects/mobile-job-notes/acceptance.md).
- Dated test and observation results in the [evidence record](../projects/mobile-job-notes/evidence.md).
- The proposed roster, response owner, and remaining questions from the [plan](../projects/mobile-job-notes/plan.md).

## Steps

1. Assemble evidence for each readiness criterion. Record missing records as pending.
2. Ask Sam to confirm that the required scenarios ran on both platforms, using the stated sample sizes.
3. Ask Priya to assess unresolved reliability risks and confirm the technical recommendation.
4. Ask Alex to confirm the operating conditions, including the roster and ownership of pilot responses.
5. Record Alex's start, hold, or stop decision in the journal. Include Priya's assessment and any conditions.
6. Update the brief and plan to match the decision. If held, name the evidence required for another review.

## Decision boundary

A start decision requires every readiness criterion to pass. A successful test on one platform does not cover the other.

This workflow records a decision. It does not send customer invitations, enable product access, or change an external system.

The next review is planned for 2026-10-13. The [2026-10-09 delivery review](../journal/2026-10-09-delivery-review.md) records why the pilot remains held pending new evidence.
