# Delivery review

Produce a decision record and an owned plan for the next week. The [routine](../routines/weekly-delivery-review.md) defines when this workflow runs.

## Before starting

Read the current [project brief](../projects/mobile-job-notes/brief.md), [evidence](../projects/mobile-job-notes/evidence.md), and [plan](../projects/mobile-job-notes/plan.md). Have the previous journal decision available.

Use manually supplied records. If a source is missing, list it as pending and identify who can provide it.

## Steps

1. Review the previous actions. Mark completion only when a dated result supports it.
2. Identify what changed in the evidence. Separate observed results from planned work and assumptions.
3. Compare the current evidence with the [acceptance criteria](../projects/mobile-job-notes/acceptance.md). Name the constraint preventing the next delivery decision.
4. Ask Alex and Priya to decide the response. Record the decision owner and any conditions; leave an unanswered decision pending.
5. Agree on the smallest next actions. Give each action an owner, expected evidence, target date, and dependency.
6. Write the dated journal entry. Include the review date, attendees, evidence, decisions, carried actions, and next review.
7. Update the project brief and plan from that entry. Check that dates, state, and the next action agree.
8. Prepare Alex's work commitments for the [shared weekly review](../../shared/workflows/weekly-review.md). Apply the [shared capacity plan](../../shared/docs/planning.md).

## Check the result

- The project state matches the journal decision.
- Every claimed completion has evidence, and every carried action has an owner.
- A proposed date remains conditional when its dependencies are unresolved.
- The next review date appears in the journal and the routine.

The [2026-10-09 entry](../journal/2026-10-09-delivery-review.md) records a completed run of this workflow.
