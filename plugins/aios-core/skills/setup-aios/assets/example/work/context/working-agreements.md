# Work agreements

Alex uses these agreements to keep product decisions traceable and limit avoidable rework.

## Evidence

- Link each progress claim to a dated observation, test result, or decision record.
- Label a target as planned until someone records completion.
- State the sample size beside a research finding. Do not turn a small observation into a customer-wide percentage.
- Treat missing evidence as pending. An empty field does not mean a test passed.

The [project evidence record](../projects/mobile-job-notes/evidence.md) lists the evidence currently available for mobile job notes.

## Decisions and communication

- Alex decides product scope and whether the pilot starts, holds, or stops.
- Priya confirms engineering readiness, supported by Sam's test evidence.
- Draft external updates for Alex to review. Preparing a draft does not authorize sending it or changing a customer commitment.
- Record decisions in the journal, then update the current project summary. Keep the original dated record intact.

## Planning

Choose work within the [shared capacity plan](../../shared/docs/planning.md). Do not assume evening studio time is available for Fieldline delivery.

Every carried action needs a named owner, an observable result, and a next review date. If a dependency prevents progress, state what must change.

## Use of records

The workspace has no connected task system or product analytics. Ask Alex for missing records instead of reporting that an external system was checked.

Use participant codes in observation notes. Do not invent customer names, contact details, or permission to recruit pilot crews.
