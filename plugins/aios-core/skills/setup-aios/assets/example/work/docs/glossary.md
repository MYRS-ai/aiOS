# Work glossary

Fieldline terms used in Alex's work. Each term is defined once, within its topic.

## Find a term

| Topic | Covers |
|---|---|
| [Product](#product) | The objects technicians and dispatchers use |
| [Delivery](#delivery) | Pilot decisions and reliability evidence |

## Product

| Term | Meaning | Notes |
|---|---|---|
| **Dispatch board** | The browser view dispatchers use to assign and sequence visits. | The mobile job notes project does not change visit assignment. |
| **Job note** | A text record attached to a visit, written by a technician for the crew or dispatcher. | A note can be saved on a device before it reaches the server. |
| **Visit** | One scheduled attendance by a technician or crew at a customer location. | Several visits can contribute to one customer's larger job. |

## Delivery

| Term | Meaning | Notes |
|---|---|---|
| **Pilot** | Limited use of a change by an agreed group before wider release. | Three crews are proposed for mobile job notes; the roster is still pending. |
| **Readiness gate** | The explicit conditions that must pass before the pilot can start or resume. | See the project's [acceptance criteria](../projects/mobile-job-notes/acceptance.md). |
| **Replay check** | A test that repeats a previously sent note submission after an interrupted response. | One note should remain after the repeated submission. |
